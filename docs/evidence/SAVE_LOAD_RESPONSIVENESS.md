## 发现与修复

CPU profile显示旧档冷加载主要耗在逐模块反复校验、复制和链接，请求总耗时
仅约0.43秒，整次却约110秒。SDK改为四并发取得缺失模块、完整校验后一次
原子安装；实例复用已验证的旧ModuleProgram，不复用任何玩家快照/profile。
生成校验器按必填唯一opcode选择原分支，仍保留字段、额外属性、ABI、摘要与
语义检查。坏候选/取消不安装部分代码，不提升指令或资源预算。

图文保存还存在重复重画未变化背景和长时间冻结剧情的问题。现在同步取得
同一切点的快照、文字、UI、像素后释放冻结，随后缩略图与存储异步完成；
持久化回执及激活隔离继续保护一致性。SVG以最多320×180栅格化。Canvas复用
完整静态帧，WebGL重画可能丢弃的前景并保留已拥有的2D背景，避免黑图/旧图。

真正的满槽测试又复现了容量拒绝：旧4M逻辑总预算在多个有效存档后触发
STORAGE_SIZE；仅压缩仍在创建第28个图文槽时失败，当时热根1747383字符、
冷记录2235368字节。SDK现采用v3逐冷记录gzip和独立64MiB冷磁盘库存上限；
实际热根（含目录）、单记录解压和读取工作集仍限制4M，wire/portable backup
上限不变。数字负零按合法JSON -0精确保留，CRC/长度/解压越界显式拒绝。

编解码在IDB事务外准备，最后核对单调根修订号并原子提交冷数据、摘要与根；
v2升级另在最终事务逐项复查旧冷值，防止同尺寸并发覆盖漏检。旧库只在成功
写入时升级，配额/冲突/失败保留原数据；没有删历史、上一修订或任何回执。
旧标签页需刷新后使用新SDK。大总库导出仍受单包/工作集边界限制；这不等于
完成W1-03C的热根拆分、回执留存或更大备份设计。

消息显隐同时修正：根opacity约束显式visible的rich glyph/Ruby，右键时窗口与
文字一起隐藏，首次step只恢复；缩略图保存正常可见内容。SDK ADR0097–0103、
G2-09/W1-08/G3-15/G4-04/W1-03C1记录完整实现与失败边界。
